# 华融人行征信异步配置示例

本示例依据《华融资信报告查询接口规范手册 V1.2.5》和[在线征信解析服务](https://s.apifox.cn/e7885bfa-c44b-4106-ad8e-c727e572c69a/api-101443425)组织配置。采用 C9004 电子授权，模型解析由征信公司封装调用，引擎只接收最终 `data`，不另外调用 `/analysis`。

## 文件与输入

| 文件 | 用途 |
| --- | --- |
| `input-object.sample.json` | 在变量管理中导入 `hrCreditInput` 输入对象 |
| `execution.mock.v2.json` | 在外数 API 的“导入链路配置”中粘贴；含三种本地请求样例 |
| `execution.pending-integration.v2.json` | 待供应商联调配置；商户及签名必填值留空，不能直接发起真实查询 |
| `response-company.sample.json` | 征信公司外层响应样例；所有值均已替换为合成值 |

样例保留原始字段名、大小写和类型，`securityComputingResult` 有 9,937 个特征字段。样例里的空字符串、0 和 false 是结构演示值，不具有业务判断含义。

`hrCreditInput` 的身份信息仅使用本地合成值。实际接入时按供应商协议加密 `queryName`、`queryIdNo`、`queryPhone` 等字段；当前示例不伪造 DES/RSA/签名实现。

| 输入地址字段 | C9004 字段 | 执行时转换 |
| --- | --- | --- |
| `caFileUrl` | `caFile` | CA 签署授权书 PDF → Base64 |
| `idCardFileUrl` | `idCardFile` | 身份证正反面合成图片 → Base64 |
| `otherAuthFileUrl` | `otherAuthFile` | 活体或手持授权材料图片 → Base64 |
| `otherFileUrl` | `otherFile` | 签署的担保申请 PDF → 单文件 ZIP → Base64 |

文件内容上限配置为 307,200 字节，图片宽高上限 1,080 像素。请求预览只显示转换占位，不下载文件、不请求鉴权或外数。真实调用在参数校验通过后下载，同一链路内相同 URL 复用下载结果；文件不合格时阻止供应商请求。

## 三步调用

| 稳定步骤 ID | 接口 | 输入与结束条件 |
| --- | --- | --- |
| `hr_authorize` | POST `/api/v1.1/C9004` | 提交电子授权，只提交一次；保存 `data.serialNumber` |
| `hr_status` | POST `/api/v1.1/C9005` | 引用授权步骤流水；每 3 秒轮询，最多 40 次；`0000` 就绪 |
| `hr_report` | POST `/api/v1.1/R9005` | 使用同一流水获取 JSON 安全计算结果，`dataType=1` |

`B0013`、`B0015`、`B0016` 属于待完成状态，只继续轮询。其他业务错误终止。各步重试为 0，避免把授权申请作为整个链路重新提交。API 总超时设为 180,000 毫秒，覆盖全部步骤和等待；两个轮询步骤不会各自额外获得完整总超时。

响应装配使用“整体取值”：`response.body.data`。变量/对象绑定时：

- 整份解析结果：`body`。
- 全部模型特征：`body.securityComputingResult`。
- 指定特征：如 `body.securityComputingResult.QYRULE001`。
- 上游原始结果仍可通过 `response.body` 或对应 `steps.<步骤ID>.response.body` 访问。

大样例自动选择整体绑定，保留可搜索的完整结构，无需创建 9,937 条映射。单个字段的取数路径和请求覆盖仍由外数变量/对象绑定面板配置。请求字段有稳定 ID，只有标记可覆盖的字段允许重新绑定。

## 本地模拟验证

在仓库根目录执行 `node scripts/mock-huarong-credit.mjs`。服务只监听 `127.0.0.1:28082`，30 分钟自动结束；验证完成应主动停止。数据源基础地址为 `http://127.0.0.1:28082`，鉴权为无；这只是协议模拟，不是供应商鉴权配置。

API 中已提供正常、白户、失败三个请求样例。正常和白户：授权 1 次、状态查询 3 次、结果查询 1 次；失败：授权 1 次、状态查询 1 次，不进入结果查询。白户状态 `02` 来自 C9005，仍可获取供应商提供的最终结果。

模拟日志 `.codex-run-logs/huarong-mock-calls.jsonl` 只记录接口名、合成流水和字段名，不记录文件 Base64 或完整报告。界面真实调用测试应使用外数追踪树检查各步状态；请求/响应预览前后模拟日志均应无新增记录。

## 真实接入前需要补齐

1. 供应商商户号、鉴权资料和实际授权的测试环境。
2. 字段加密、请求签名、响应解密的完整算法与可核对样例。手册中的 R9005 描述可能返回 RSA 密文；本示例按用户确认的目标形态将公司最终 `data` 当作结构化解析对象，若实际返回密文必须先增加解密处理。
3. 供应商实际计费规则。本示例不启用计费条件，也不凭 HTTP 200 推定应计费。
4. 使用获授权的测试身份与签署文件验证供应商端验签和材料审查。

本示例采用轮询。供应商 RSA 回调验签与引擎现有 HMAC 回调协议不同，不能直接互换；如切换回调，需要对照供应商签名协议单独接入。
