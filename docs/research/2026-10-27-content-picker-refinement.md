## 后续反馈：表格铺满与编辑性能（2026-10-27 18:02）

### 修复

- 原先手动列宽把表格总宽固定为像素值，面板变宽后右侧出现空白。现在将保存的列宽作为分配比例，按照明细区实际宽度计算四列；拖动某列时联动其他列，保持总宽不变。达到最小宽度的列不再收缩，极窄窗口才使用必要的水平滚动。旧列宽偏好直接兼容，不需要清空浏览器数据。
- 编辑卡顿来自脚本每次输入重新生成两万级引用目录、重注册提示服务，以及父子组件重复扫描与立即刷新标注。现在按资源与稳定绑定变化缓存目录索引，设计器与 Monaco 共用解析结果，并将同一动画帧的标注更新合并。原始脚本的输入事件仍即时发送；没有延迟保存、改写代码或取消原生撤销。
- 提示服务保持实例稳定，资源名称或 ID 绑定变化后正确更新。目录索引按 ID 解析显式绑定，失效 ID 不会回退到同名资源。

## 后续复盘：全局历史规则空目录与剩余留白（2026-10-27）

### 原因与实际证据

- 全局字段并未丢失。真实后端 `/api/rule/variable/project/0` 返回 255 个全局字段（235 个变量、20 个常量）。
- 全局规则 162 的生产版本 105，以及截图对应规则 163 的生产版本 106，引用目录均为 `AVAILABLE / ARTIFACT_SOURCE`，但保存的变量、对象与固定版本元数据为空。另一全局规则 164 的版本 107、108、109 均有冻结变量和固定版本元数据。问题与旧制品内容有关，不能把所有全局规则判为加载失败。
- 前端把“历史版本未保存字段目录”显示成普通的“没有符合条件的字段”；且切换当前目录后，原来的“已选内容 0”或旧搜索可能继续隐藏当前字段。
- 另一个兼容性缺口是：标明 `GLOBAL` 但未填写 `projectId` 的历史规则，会提前返回空目录。现在明确按全局范围使用 `0`，不修改规则记录本身；项目规则确实缺少所属项目时显示加载失败。
- 表格剩余留白的原因是列轨道仍使用上一轮计算的像素值。即使表格外壳宽度为 100%，尺寸通知延迟后内部列的总宽度仍可能偏小。旧测试只校验表格外壳宽度，本次补充检查最后一列实际右边界；旧实现稳定复现约 97px 留白。

### 修复后的操作

1. 旧历史目录为空时，状态区和内容选择器明确说明原因；允许本地编辑时，内容选择器直接提供“加载当前可用字段”。
2. 点击后通过原有受权限约束的目录切换流程加载当前资源，并清除空的已选分类与旧搜索，直接展示全部可用内容。未完成本地绑定或无编辑权限的来源不提供该入口。
3. 当前目录仅用于用户主动编辑，未用当前资源偷偷补写旧制品；原生产版本、脚本中的稳定 ID 和固定版本号保持不变。
4. 表头和数据行改为原生 `minmax(..., ...fr)` 弹性网格，宽度直接为 100%。容器变化立即由 CSS 分配列宽，不依赖尺寸观察回调更新才能铺满；开始拖拽或键盘调宽时重新测量当前可用空间。
