## 性能与正确性证据

A15 使用同一个[制品加载探针](E:/workspace/tianshu-decision-engine/docs/research/2026-09-13-selected-evidence/ArtifactLoadProbe.java)在修改前后测量：内存中约 1.07 MB 制品，含 1 MB 二进制附件和 100 个变量；预热 20 次、测量 200 次，读取依赖的数据库调用被内存夹具替代。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 平均加载耗时 | 2.234 ms | 0.483 ms |
| P50 | 2.103 ms | 0.471 ms |
| P95 | 3.133 ms | 0.527 ms |

这些数据只说明该探针下的制品加载收益，不是生产 QPS 或完整决策接口延迟。仍然读取实际制品内容与部署绑定，每次仍创建独立变量和模型；没有把可变运行对象跨请求复用。64 MiB 是组件内容及序列化元数据预算，并非 JVM 总堆占用的精确上限。

A17 使用容量为 8 的缓存，持续读取同一热规则并插入 1000 个冷规则。原策略产生 992 次热规则未命中；新策略为 0。另覆盖快照构建期间读取不阻塞、增量写入与快照提交顺序、快照移除旧规则、超限快照保留热项且使用新版本（包括更低版本的权威回滚）。淘汰候选的扫描发生在写入路径，不在每次读取时扫描缓存。

其他回归点包括：字段改名后的 ID 引用、NULL/false/前导零字符串保真、冻结执行引用、数据库绑定两种历史键名、缓存命中时的字节/摘要篡改、部署绑定更新、缓存容量上限、校验锁版本变化、权限限制和原始 JSON 解析失败时保留内容。

## 操作变化和边界

- 变量列表默认展示业务关键字段，需要技术详情时勾选“显示脚本名称、默认值和取值范围”；转全局、枚举选项和删除仍可在更多菜单中访问。
- SQL 参数中的新业务引用按 `refType + refId` 保存。旧字符串表达式不自动转换；选择新类型时才转换该参数。前端和后端需要一起更新，以识别新的类型化参数结构。
- SQL 仍直接编辑。只允许单条 SELECT；CTE、数据库间有歧义的转义、可执行注释等没有被扩大为支持范围。实际只读边界仍依赖只读数据库账号。
- A05 检查的是规则模型的字段稳定引用，不是外数可达性、全量运行依赖或发布容量认证。工作台仍明确提示发布需要校验与审批。
- A07 对可以对应到节点或行的位置执行聚焦；其他路径进入确切修订并给出配置位置和修复说明，不猜测资源关联。
- 没有数据库迁移，没有改变一级导航、SQL 直接编辑、用户编码或已发布制品。改动留在 master 工作区，未提交、未推送。
