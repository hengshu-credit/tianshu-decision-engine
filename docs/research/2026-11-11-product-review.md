# 天枢决策引擎产品与实现核查

核查日期为 2026-11-11。起点为 `master` 的 `366195ce34c5e569f376c98c56feaaead3b9bfa7`。范围取自实际注册的 20 个一级入口、9 个规则设计器、5 个 Maven 子模块和服务端 46 个带 `@RestController` 的类。问题从当前入口、正常用户操作、执行代码和测试契约推导。对应的需求、优先级和验收条件见[功能优化计划表](../plans/2026-11-11-product-requirements.md)。

## 用户要完成的事

| 角色 | 起点与任务 | 怎样判断完成 |
| --- | --- | --- |
| 策略配置人员 | 项目中已有客户字段，以年龄、额度或名单命中为条件，配置准入、评分或定价 | 能按业务名称选字段，选择运算、动作与结果类型；保存后重开仍是同一字段，正常、边界、未命中样例都有预期结果 |
| 数据与模型维护人员 | 供应商给出接口样例、数据库列、文件目录或模型文件 | 能分清输入、返回结构和模型输出，用已声明结构接入规则；供应商换结构后能找到受影响的引用和验证样例 |
| 测试与审批人员 | 收到一份待发布修订，线上已有生效版本 | 能指出本次测哪份配置、可能调用或写入什么、预期如何校验；能核对所批修订和回归证据 |
| 接入人员 | 选择项目令牌，通过服务端 OpenAPI、Java SDK 或独立 runtime 发起调用 | 在明确的项目和版本获得一致业务输出，用 trace 找回执行身份、外部调用、失败原因与费用 |
| 项目管理员与运维 | 将规则交给其他团队使用，或处理线上失败、迁移、升级 | 项目权限能约束各入口，能还原谁操作了哪条记录；可判断发布、同步、上报及备份恢复各自是否成功 |

## 从配置到执行

1. 管理控制台用路由、页签和项目上下文组织工作。内容选择器读取变量、数据对象、模型、函数和外数目录。业务引用携带资源类型和 ID，固定版本另带版本身份。外部报文中的属性使用其协议路径。
2. 设计器保存结构化模型。模型层承载字段和测试契约，核心模块各编译器通过 `VarContext` 解析引用并生成执行脚本。工作区、草稿修订、冻结制品与业务版本有各自的身份。审批和固定用例校验是发布流程的一部分。
3. 服务端 OpenAPI 负责项目调用入口、参数映射和执行。SDK 通过 HTTP 同步并在进程内缓存，Redis 通知变更。独立 runtime 包装 SDK 的本地执行。日志默认经 HTTP 批量上报，配置 Kafka 时有独立的队列和回补路径。
4. 运营端通过执行日志、调用日志、账单、审批和账户操作日志回答不同的问题。离线迁移承载资源及其依赖；部署工具另行处理应用制品、历史版本、数据库迁移和恢复。

实现入口见[前端路由](../../rule-engine-web/src/router/index.js)、[根 POM](../../pom.xml)、[核心编译器](../../rule-engine-core/src/main/java/com/hengshucredit/rule/core/compiler)、[测试目标解析](../../rule-engine-server/src/main/java/com/hengshucredit/rule/server/service/RuleTestTargetResolver.java)、[SDK](../../rule-engine-client-sdk/src/main/java/com/hengshucredit/rule/client)和 [runtime](../../rule-engine-runtime/src/main/java/com/hengshucredit/rule/runtime/RuntimeController.java)。

## 九类设计器的业务验收口径

| 模型 | 无需手写 QL 的主任务或脚本模型的专属任务 | 需要验证的结果 |
| --- | --- | --- |
| 决策表 | 依次选条件字段、比较符、阈值、输出字段与动作 | FIRST、ALL、UNIQUE 对多命中的处理，未命中及行顺序，字段改名后重开 |

| 规则集 | 配条件树、优先级、执行模式与命中动作 | 首条或多条命中、命中集合、输出和日志归因 |
| 交叉表 | 选行列字段和结果字段，填交叉格 | 区间端点、空格、默认结果和写入对象 |
| 复杂交叉表 | 选多层行列维度、分段及输出字段 | 组合数、各维度端点、默认值和编译耗时 |

| 核心与 SDK | `QLExpressEngine.prepare` 对解析结果使用有界缓存；SDK 的 `L1MemoryCache`、HTTP 同步和 Redis 订阅分别承担本地命中、取版本和更新。 | 冷启动、热命中及发布后首次调用要分别测量。管理端单次耗时无法给出 SDK 容量。 |
| 大配置与大列表 | 复杂交叉表编译器展开多维分段组合。项目工作台批量取规则内容、按所属项目复用目录，再逐条解析。日志逻辑视图支持分页；SDK 日志队列有界且批量发送。 | 优先测量维度数、规则数、积压和慢查询。具体容量目标需要按真实拓扑、数据分布和成功率给出。 |
