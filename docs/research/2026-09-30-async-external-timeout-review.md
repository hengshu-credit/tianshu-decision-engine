# 异步外数等待预算复核（2026-09-30）

## 发现

外数接口原先只有一个 `timeoutMs`。它既用于单次同步 HTTP 请求，又被 `RequestDeadlineContext` 当作整个异步提交、轮询或回调链路的总预算。控制台默认值为 3000 毫秒，而默认轮询间隔为 3000 毫秒、最多 20 次；异步供应商还未完成任务时，回调 Redis 键也会随总预算过早过期。

## 修复

- `RuleExternalApiConfig` 新增 `asyncTimeoutMs`，默认 30000 毫秒，允许范围 1000 到 86400000 毫秒。
- 异步调用使用 `asyncTimeoutMs` 建立总等待截止时间；同步调用继续使用 `timeoutMs`，单次 HTTP 连接/读取超时语义不变。
- 控制台异步结果配置显示“异步等待超时毫秒”，与同步超时分开填写。
- `schema.sql`、运行时 Schema 同步和独立迁移 SQL 均补充字段，旧环境升级不依赖手工改表。
- 异步配置校验在保存/调用前拒绝无效等待预算，避免配置看似成功但必然在第一次轮询前超时。

## 验证

- `ExternalApiConfigValidatorTest` 新增独立预算测试：同步 3000 毫秒、异步 60000 毫秒可以通过；小于 1000 或超过 24 小时会被拒绝。
- 外数配置前端相关测试 44 项通过；服务端定向测试和全模块构建通过。

## 边界

异步等待预算仍受业务请求整体网关、线程池和供应商 SLA 限制；本修复只避免引擎自身用同步短超时提前终止异步链路。高并发回调仍需要目标部署验证 Redis、网关和供应商回调重试策略。
