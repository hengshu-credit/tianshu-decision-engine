# 公共版本管理

## 版本语义

- 资源 ID 不随版本变化；业务版本号和不可变修订号分开。最新版是当前生产指针，指定版绑定业务版本，其覆盖记录保留完整历史。
- 保存只创建或修改草稿。发布经过现有依赖检查、审批和模块发布适配器；生产内容和多个草稿、不同版本的审批可并存。
- 基于任意历史修订编辑，可以新增业务版本或覆盖选定业务版本。覆盖前校验目标修订，避免丢失并发修改；覆盖旧业务版本不倒退最新版。
- 删除草稿只终止该草稿。删除版本为逻辑删除，保留快照、审批、执行与计费证据；当前生产版本和仍被引用的版本需要先处理依赖。
- 预览、比较和变更记录按不可变修订读取；执行和迁移明确选择最新版或指定版本，禁止以当前内容代替历史内容。

## 实施路径

1. 复用 governed_resource、governed_resource_version、governance_approval_request 以及各资源适配器，统一接口和审批版本上下文。
2. 公共版本面板提供草稿、生产版本、历史修订、预览、差异、编辑、审批和迁移操作，各模块共享。
3. 保留已有规则版本绑定和字段固定快照兼容，新增业务版本选择语义。
4. 贯通测试、执行日志和账单的版本身份及过滤。
5. 前后端完整构建、测试、启动验证和浏览器操作；记录未完成项，禁止将部分验证作为全量验收。

## 已实现

- 公共 `ResourceVersionManager` 用于变量、数据对象、规则、模型、外数数据源/API、函数、分流、项目、名单和计费配置的版本入口；列表操作区提供显式按钮，详情页复用同一组件。
- 公共面板支持生产版本与多个草稿并存、选择任意已保存修订、业务字段编辑及高级配置、预览、任意修订对比、变更记录、提交发布审批、删除草稿、删除非当前生产版本和迁移包下载。
- 沿用原治理表。发布草稿新增 `publishMode`、`targetVersionId` 和 `expectedTargetSnapshotId`，独立版本草稿不再占用资源级单一活动键。不同版本可以并行审批；覆盖目标变更时返回冲突；草稿保存校验摘要。
- 覆盖产生新修订，旧快照不改写；覆盖旧业务版本时恢复当前生产投影并抑制函数推送、外数计费配置同步等非最新版副作用。模型文件使用原生不可变版本 ID 关联，并在数据库内复制，版本列表不复制大型模型文件。
- 字段选择新增 `BUSINESS_VERSION`，按资源 ID 和业务版本解析当前修订；一个执行上下文固定本次解析结果。原不可变快照引用保持兼容，资源版本的实际修订写入执行追踪。
- 规则测试新增 `LATEST` 和 `BUSINESS_VERSION`，同时保留草稿、画布预览和不可变快照测试；分流实验支持指定版本执行，并按所选快照生成测试入参。
- 日志与账单复用规则版本筛选组件，支持全部、当前最新版和指定业务版本。账单新增规则 ID、执行版本、修订 ID 和制品摘要；引擎计费及根规则内的 API 计费均携带实际执行身份，恢复写入不改用新的生产指针。
- 新库 DDL 与已有库 SchemaSync 均包含新增列；旧账单缺失的执行身份保持为空，不按当前版本补造历史数据。

## 明确边界

- 当前生产版本和仍有资源依赖的版本不允许直接删除；删除保留审计快照。目前删除依赖检查采用资源级保守判断，尚未细化为仅检查该业务版本的消费者。
- 跨环境固定依赖通过用户明确选择目标环境已有的已发布版本完成映射；不会自动猜测版本等价关系、复制整条历史或覆盖所选依赖。缺少目标版本时需先迁移并发布依赖资源。动态计算的脚本资源/版本 ID 无法安全静态映射，会明确提示改为可识别的静态 ID 后再迁移。
- 早期原生规则、模型、函数、实验快照保留在公共面板的“早期历史快照”入口；没有自动改写旧版本号或为缺失的历史快照伪造可执行制品。
- 浏览器完整操作覆盖独立变量、规则、跨资源版本迁移和分流实验；模型、外数等还通过公共面板检查及对应自动化测试验证，未对所有既有业务模型逐一做真实发布或大模型容量验证。
- 未重启其他任务的服务；现有部署需重新加载代码及执行已有库结构升级才能启用新增功能。
