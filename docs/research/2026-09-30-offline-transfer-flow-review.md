# 离线迁移流程复核与修复（2026-09-30）

## 本轮范围

依据实际 `OfflineTransfer.vue`、迁移预检/导入控制器、导入服务和现有远程选择组件复核。沿用一级菜单平铺及全局/项目作用范围；修改只涉及迁移页面和对应回归，未修改同时进行中的外数执行重构。

## 已复现并修复

| 问题 | 影响 | 修复 |
|---|---|---|
| 预检后修改项目、范围、覆盖/复用策略、后缀或发布选项，旧报告仍可确认 | 用户确认的内容与实际提交选项不一致 | 预检绑定文件对象与规范化选项；选项修改立即作废报告；提交方法本身再次校验 |
| 更换文件或发起新预检后，慢请求回写旧报告 | 显示错误资源或冲突，恢复不应可用的导入按钮 | 请求序号及文件/选项双重校验，只接受当前请求；旧请求的结束不能重置新请求状态 |
| 重新预检失败仍保留旧报告 | 失败后还能用旧结果提交 | 预检开始即清空旧报告；失败原位显示错误；缺少包摘要的响应不可作为有效报告 |
| 确认弹窗前未上锁、请求读取可变表单 | 连续点击可弹多个窗口并重复导入 | 从弹窗开始到导入完成使用同一提交锁；冻结提交参数；弹窗返回后再次检查预检身份 |
| 取消确认抛出异常、导入完成后可重复提交 | 未处理异常或重复新建资源 | 正常处理取消；成功或请求失败后要求重新预检，失败不显示成功结果 |
| 项目级导入要求手工填写内部 ID | 业务人员需要另找项目 ID，易绑错 | 复用分页远程选择组件，按名称/编码查询和展示，以稳定 ID 提交 |
| 全局确认文案仍称绑定项目，发布后结果仍称草稿 | 用户难以确认实际归属和生效状态 | 按全局/已有项目/新项目显示确认说明；按本次提交的发布选择显示结果；全局请求清除残留项目参数 |

## 第二轮：服务端项目归属修复

### 问题与行为

- 原先项目也进入普通资源的 `REUSE/OVERWRITE/SUFFIX` 分支。绑定已有项目并选择覆盖资源时会被拒绝；选择新建项目时又可能按源项目编码复用旧项目。现在项目只按显式目标 ID／源项目 ID 映射绑定，或按新建选项创建，不通过同码项目猜测归属。
- 非项目资源的冲突查询使用实际解析后的目标项目，修复映射到项目 42、却在默认项目 99 查找并覆盖资源的错误路径。
- 整包目标项目先行检查，不存在／已删除的目标会在产生治理写入前被拒绝；新建和已有绑定的矛盾选项也提前拒绝。
- 全局导入跳过项目模板，不受残留新建标记影响；不包含项目模板的全局资源包，现在也可以使用填写的新项目编码和名称创建目标项目并绑定资源。
- 预检同步归属逻辑：明确绑定或全局跳过的项目不再因源编码相同而报冲突；新建项目按目标编码查冲突；资源预检使用源项目映射；新建项目不再误报“需要选择已有项目”。
