## 第三轮：资源复用一致性修复

### 已修复

- 导入原先命中同编码资源就直接复用，未验证变量类型、函数实现、启用状态等。现在普通变量仅在同码、同类型且常量/非恒定变量类别一致时允许显式复用；其他资源必须在目标引用 ID 重写后配置相同且处于启用状态。
- 预检和实际导入共用比较逻辑，均按依赖顺序处理。预检使用已确认的目标资源/子字段 ID 比较；将新建的依赖尚无目标 ID 时，不把依赖它的资源误报为配置完全相同。
- 原来的递归比较会删除业务报文中的 `id/projectId` 和真实外数 `datasourceId`，导致不同配置误判相同。现在只在明确的资源实体边界去除身份和审计元数据，保留业务 JSON 和依赖 ID，并解析已知 JSON 配置字段后比较。
- 已复用的数据对象在确认字段顺序、结构和配置完全一致后，按对应字段位置建立源/目标 ID 映射，避免 `father.age`、`mother.age` 等不同分支的同名字段被错误关联。
- 含环境凭据的配置不能仅凭双方都有“已配置”标记证明相同，会返回 `ENVIRONMENT_REVIEW_REQUIRED`；模型则恢复治理快照中的模型内容后参与比较，不能只比较模型名称和参数。
- 配置不一致、类型冲突或停用资源选择“复用”时，预检说明原因并建议新建后缀，实际导入再次拒绝错误复用。

## 第五轮：覆盖保护、资源选择和设计器状态

### 覆盖保护

- 数据对象覆盖不再把源环境字段数字 ID 直接用于目标环境 UPDATE。迁移会按完整父链的原样字段编码、类型和泛型匹配目标字段；未匹配字段使用不与目标字段冲突的临时负 ID，审批落库后再组合为源字段 ID → 实际目标字段 ID。
- 删除字段、改变字段类型或泛型前，治理预检和实际适配器写入前都会检查目标环境仍生效的结构化消费者：规则输入/输出和模型输入/输出、规则内容与有效修订、仍启用的函数参数、变量来源、外数 API/鉴权、分流条件、其他数据对象引用，以及仍生效的固定规则版本快照。只读取配置和引用列，不读取模型二进制、执行日志或历史制品。
- JSON/Java/DDL 数据对象的业务样例不会被递归当成引擎关联；API/DB 来源配置仍会按外数/数据库取数配置检查。复杂动态脚本无法静态识别的边界在治理提示中保留，不能被误判为无引用。

### 资源选择和查询

- 离线导出改为名称/编码远程搜索，资源选项携带作用范围、项目名称/编码和稳定 ID；支持多根资源去重、类型切换清空旧 ID、候选请求失败后重试。新增 `/api/rule/transfer/resources` 使用 `rule:view` 权限，避免迁移用户必须拥有审批查看权限。
- 血缘 options 保留原数组响应兼容，并支持分页查询；补充函数和分流实验候选，候选查询按数据库端编码/名称过滤，避免原来只截取前 80 条和一次性读取大字段。
- Element Plus 的 `visible-change` 在加载中或空候选时会产生假关闭事件，导致重复请求和候选消失。远程选择器改为监听真实 `expanded` 状态，对相同关键词的进行中请求去重，失败可重新搜索。

### 设计器状态
