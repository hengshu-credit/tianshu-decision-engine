# 数据对象数据库来源缓存复核

## 发现

数据对象来源解析原来使用 `DATA_OBJECT_SOURCE:{objectId}` 作为根执行缓存键。一个对象的不同子字段可以通过字段级 `sourceConfig` 覆盖 SQL 或参数；这些绑定共享对象 ID，但实际查询不同，会导致后一次查询复用前一次结果。

## 修复

缓存键现在包含项目、对象 ID、来源类型、完整来源配置、数据源 ID、SQL、绑定参数和查询限制的摘要。不同 SQL、参数、覆盖配置不会互相复用；相同查询仍保留 single-flight，避免重复数据库请求。

API 数据对象来源的等待任务也会把 pending 任务信息写入根执行检查点，恢复规则时沿原任务继续查询，不重新提交外数任务。

## 验证

新增回归用例覆盖：同一对象 ID 的不同 SQL 返回不同结果、两次查询分别执行，以及 API 数据对象来源等待状态持久化。
