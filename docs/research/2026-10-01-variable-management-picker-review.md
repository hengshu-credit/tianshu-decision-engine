# 变量管理与字段选择器评审（2026-10-01）

## 1. 当前实现结论

变量管理页已经覆盖四类业务对象：变量、数据对象、常量和字段校验规则；新增与编辑多数复用同一个弹窗，通过当前页签和对象 ID决定标题、字段和提交动作。页面还具备配置步骤引导、来源目录过滤、预览结果、对象字段引用校验、导入帮助和审批草稿。

当前主要问题是“引用入口不统一”：设计器、衍生变量和名单查询已经使用 `OperandPicker`，但对象字段引用和 SQL 参数仍分别使用普通 `el-select`。用户在不同区域需要重新理解变量、常量、对象字段、模型输出和方法的展示方式，也容易把技术名称当作稳定引用值。

目标交互应统一为：

```text
资源类别 → 搜索编码/名称 → 查看类型与来源 → 选择稳定 ID → 显示当前绑定 → 可重新校验
```

所有引用仍保存 `refType + refId`；编码、名称、脚本名和导入字段保持用户输入原样。选择器只是展示和绑定工具，不负责自动改名或猜测同名资源。

## 2. 页面结构与用户路径

| 页签 | 业务任务 | 当前入口 | 目标交互 |
|---|---|---|---|
| 变量列表 | 管理输入、计算、接口、数据库、名单和衍生变量 | 表格 + 新建/编辑弹窗 | 保留列表筛选；新增和编辑共用同一配置表单，按来源显示专属区块。 |
| 数据对象 | 管理对象结构及字段 | 对象表格 + 展开字段 + 对象/字段弹窗 | 对象定义和字段编辑复用范围、类型、来源和引用选择器。 |
| 常量列表 | 管理有默认值的常量 | 常量表格 + 共用变量弹窗 | 通过来源固定为常量，默认值和类型在同一表单内完成。 |
| 字段校验 | 管理可复用校验规则 | 校验表格 + 独立校验弹窗 | 保留内置规则只读；自定义规则复用统一作用范围、项目、状态和审批底栏。 |

业务人员的主路径应是“先选归属和字段含义，再选来源，最后用样例预览”。SQL 型用户仍可直接编辑 SQL，但参数和结果路径使用字段选择器及结果预览辅助完成。

## 3. 统一字段选择器的资源范围

| 资源 | 选择器展示 | 保存形式 | 当前支持情况 |
|---|---|---|---|
| 普通变量 | 编码、名称、类型、项目范围 | `VARIABLE:id` | 已支持。 |
| 常量 | 编码、名称、默认值、类型 | `CONSTANT:id` | 已支持。 |
| 数据对象字段 | 对象分组、相对路径、字段名、类型 | `DATA_OBJECT:id` | 已支持。 |
| 模型输出 | 模型分组、输出路径、类型 | `MODEL_OUTPUT:id` | 已进入统一引用目录。 |
| 方法/函数 | 方法名、编码、参数数量和返回类型 | `FUNCTION:functionId` + 参数树 | `OperandPicker` 与表达式编辑器已支持。 |
| 外数结果 | API 结果模块路径、返回类型 | 外数上下文引用或路径 | `ApiSourceBinding` 已支持结果模块和参数覆盖。 |
| 名单查询 | 名单库、字段、组合命中模式 | `LIST_QUERY` 表达式 | 表达式编辑器已支持，变量来源页已接入。 |
| 数据库查询 | SQL 参数顺序、字段来源、结果路径 | 参数 `REFERENCE` 操作数 | 本轮已改为统一 `OperandPicker`。 |

对 API、数据库和名单本身的“资源选择”仍属于数据源配置选择，应使用带项目范围、状态和来源说明的资源选择器；它与字段引用选择器共享搜索、分组、禁用项和失效回显规则，但不能混淆资源 ID 与字段 ID。

## 4. 本轮已实施

### 4.1 `VarPicker` 增加混合引用输出模式

`src/components/common/VarPicker.vue` 新增 `valueKey="reference"`：

- 选择普通变量、常量、对象字段时输出 `refType:id`；
- 通过 ID 和引用类型回显当前值，编码改名后不丢失绑定；
- 仍支持原有 `code`、`id` 和操作数模式；
- 新增 `disabled` 属性，弹窗加载/校验期间不会误打开或写入。

### 4.2 对象字段引用改用统一选择器

变量管理的“引用变量”字段从普通 `el-select` 改为 `VarPicker`：

- 继续只展示启用、作用范围兼容、类型兼容的变量、常量和数据对象；
- 仍使用原有 `VARIABLE:id` / `OBJECT:id` 兼容后端校验和提交逻辑；
- 失效引用仍能回显原值并显示错误，不会按名称自动替换；
- 校验成功后仍由 `validateDataObjectFieldReference` 决定是否写入表单。

### 4.3 SQL 参数改用 `OperandPicker`

`SqlParameterEditor` 的“业务字段”参数不再用普通下拉框，而是统一字段选择器：

- 可从统一引用目录选择变量、常量、对象字段和模型输出；
- 保存完整 `REFERENCE` 操作数，保留 `refType`、`refId`、类型和编码；
- 旧代码调用 `selectReference(index, 'VARIABLE:id')` 仍兼容，历史测试和旧交互不会失效；
- SQL JSON 模式和用户原有表达式保持不变。

### 4.4 规则设计器可直接引用外数上下文

设计器加载项目资源时同时加载启用的外数 API。字段选择器按 API 分组提供：

- 请求 URL、方法、Header、Query、Body；
- 响应 HTTP 状态码、响应 Header、原始响应体、组装结果；
- 调用结果、重试次数、是否计费、是否熔断、异常标记、调用 ID 和耗时。

选择后保存为 `EXTERNAL_API:apiId + relativePath`。编译结果使用请求级 `externalApiValue` 读取函数；运行时通过当前执行会话的外数缓存按需取值，因此同一次规则执行中选择多个 Header/状态/响应字段不会重复调用供应商。制品部署通过 `BINDING:EXTERNAL_API:apiId` 重新绑定目标 API，保留现有鉴权、项目范围、重试、计费和 single-flight 机制。

## 5. 仍需继续的高价值改进

本轮新增 `ScopeProjectFields` 和 `ManagedDialogFooter` 两个共享组件，变量、数据对象和字段校验弹窗共用作用范围/项目选择和审批底栏；数据对象提交增加加载态和重复提交保护。

1. 继续将变量、对象字段和校验规则中的字段定义区块抽成小组件。`ScopeProjectFields` 和 `ManagedDialogFooter` 已完成，父页面仍保留数据装配、来源切换和 API 提交。
2. 抽取 `ResourceReferencePicker`，统一 API、数据库源、名单库和模型资源选择；选项显示“名称 / 编码 · 项目范围 · 状态”，审批中、停用、无权限和加载失败分开表达。
3. 把字段选择器的类别说明、搜索、类型徽标、空态和失效回显做成可配置槽位，避免每个页面再次实现下拉选项文本。
4. 校验规则编辑器增加按校验类型的结构化输入：正则预置、数值范围、长度范围和集合值共享同一校验值组件；保存前即时显示示例输入和失败提示。
5. 新增/编辑/切换页签时统一脏数据保护；关闭弹窗、切换项目或离开页面时说明“草稿未提交审批”，保留当前表单。
6. 对方法、模型、外数、名单和数据库选择增加“查看详情”快捷动作，但动作只打开对应管理页面，不自动修改当前引用。

## 6. 验收标准

- 变量、常量、对象字段、模型输出和 SQL 参数在可引用场景中使用同一套选择器语言和 ID 绑定规则。
- 方法参数和名单查询仍使用表达式编辑器，字段、常量和模型输出可以从同一资源目录插入。
- 变量编码或名称变化后，已保存引用通过 ID 正确回显；同名资源不能被误替换。
- 对象字段引用类型不兼容、作用域不兼容、停用或删除时，用户能看到原因并在原位置重新选择。
- 新建和编辑弹窗在变量、对象、常量、校验四类页签都能完成：填写 → 预览/校验 → 生成审批草稿；失败不清空输入。
- `npm run dev` 页面无控制台错误；相关 Vitest、管理页 E2E、字段选择器 E2E 和 1280×720 UI 质量检查全部通过。
