03 / PROJECTS & ACCESS

登录、选择项目，再开始配置

项目是规则和资源的边界。进入设计器、执行测试、查看日志前，先确认顶部当前项目与自己的角色权限。

操作步骤

  1. 输入账户信息登录；若菜单缺失，先让管理员检查角色权限。
  2. 进入“项目管理”，从列表打开目标项目的工作台。
  3. 在项目详情确认规则、变量和外部资源是否属于同一项目。
  4. 需要接入业务系统时，在访问鉴权中创建并复制项目令牌。
权限先于按钮

按钮是否出现只反映当前页面权限，服务端仍会再次校验。遇到 403 时，记录项目、动作和时间交给管理员处理。

令牌只显示一次

创建或轮换后立即放入安全存储；不要把令牌写进规则、截图或前端代码。

04 / DATA & RESOURCES

先把输入和依赖准备好

规则设计器只负责组合逻辑。变量、数据对象、名单、外数、数据库、模型和函数应先单独配置并完成可用性检查。

A

变量与数据对象

在变量管理创建输入、计算、常量、API、数据库或名单变量；数据对象用于组织嵌套字段。导入 Java 实体、JSON、DDL 后，展开对象核对字段类型和引用变量。

  • 字段和变量通过稳定 ID 关联，编码按输入原样保留。
  • 先保存数据对象，再在规则输入字段中选择它。
B

外数、数据库与名单

外数 API 配置请求、响应映射、鉴权、超时和重试；数据库仅配置只读账号与查询类 SQL；名单维护记录并查看匹配日志。

  • 外部资源上线前，先使用“测试”按钮核对响应结构。
  • 敏感凭证放在鉴权配置，不要拼进 URL 或规则脚本。
C

模型与函数

模型页面配置入参、出参、版本与执行测试；函数页面登记 QLExpress、Java 类或 Spring Bean，供设计器动作和表达式复用。

  • PMML / ONNX 字段名按模型声明精确匹配。
  • 函数修改后，回到引用它的规则重新执行测试。
05 / DESIGN, TEST & RELEASE

设计规则：输入、逻辑、输出三件事

进入“规则管理”新建规则，先选择模型类型，再在设计器完成输入字段、条件与动作、输出字段配置。页面顶部的“暂存保存配置”和“保存并编译”含义不同：前者只保存当前配置，后者会编译并更新可测试版本。

1配置输入输出选择已有变量、数据对象或模型输出
→
2编辑条件与动作选择变量、运算符、常量与动作
→
3保存并编译查看校验位置与编译结果
→
4测试后发布通过预检、审核和发布流程

TRACE TREE / 09 VIEWS

九类设计器的表达式追踪树

配置完成后，从追踪树确认实际命中路径、条件结果和动作输出。

配置时记住三点

01

引用用 ID
变量、模型和字段的关联依赖稳定 ID，不要手填名称替代选择器。

02

脚本先预览
可视化配置和脚本预览应表达同一份模型，保存后再编译。

03

发布有版本
编辑草稿不会改写已发布制品；发布前要确认版本摘要。

TEST

执行测试并看懂追踪

  1. 在“规则测试”选择项目和规则，加载输入字段。
  2. 填写一组代表性样例并保存为测试用例。
  3. 执行后先看输出，再打开“表达式追踪树”确认命中行、分支、评分项或脚本表达式。
  4. 边界值、缺失值和外部资源失败场景都要各测一组。
RELEASE

提交审核、预检并发布

在规则详情页按“保存 → 依赖预检 → 提交审核 → 审核通过 → 发布”的顺序操作。预检会提示输入输出、引用资源和版本问题；发布后使用执行日志确认线上调用的是哪个修订版本。

06 / OPERATIONS & GOVERNANCE

发布以后，继续看运行证据

规则上线不是终点。执行日志、血缘、分流实验和账单把每次决策的输入、结果、依赖与成本串起来。

↯

执行日志

按项目、规则、时间和状态筛选调用，打开详情查看输入输出、耗时、修订号和追踪树。

⌘

血缘分析

从变量、规则、模型、外数、数据库和名单查看上下游。结构化引用可追踪，动态脚本引用需要结合代码复核。

⚑

分流实验

配置冠军、挑战和测试组，选择条件或流量路由，并保留实验版本与结果。

¥

账单管理

按引擎执行、API 调用和数据库调用配置计费项，查看明细和汇总。

当前实现边界

  • 血缘对脚本中的复杂动态引用只能做静态识别，关键变更仍需人工复核。
  • 数据库管理面向只读账号和查询类 SQL；正式交付仍应完成真实环境 E2E、容量、备份恢复和灾备演练。
  • 外数、数据库和名单变量的在线测试依赖对应数据源可用，失败会写入模块日志。
