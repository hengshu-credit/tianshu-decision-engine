# 天枢决策引擎功能优化计划与需求

版本：独立重梳 V1，2026-10-27。依据：[本次全模块研究](../research/2026-10-27-engine-product-review.md)。条目来自当前代码与本次验证，不继承历史计划的优先级、排期或完成标记。

逐项修复及逻辑、真实 UI 验证依据见[本轮实施记录](../research/2026-10-27-optimization-implementation.md)。下表按实际完成范围更新，不将部分修复等同于整项产品需求完成。

## 1. 产品目标与边界

让业务配置员能回答五个问题：当前在改什么、数据从哪里来、修改何时生效、测试会做什么、失败后应该去哪里处理。让接入和运维人员能解释版本、资源容量、依赖调用和故障恢复。

必须保留：

1. 一级菜单平铺和现有模块入口。
2. 直接 SQL 配置能力；按实际职责提供辅助说明。
3. 引用以稳定 ID 和 `ref_type` 关联，版本身份明确。
4. 用户输入的编码、名称、字段、大小写及导入内容原样保留。
5. 资源草稿与审批、发布制品不可变、冻结依赖及回归证据。
6. 模块/项目/全局权限，凭据三态语义，账户变更导致旧会话失效。
7. 已有接口、SDK、返回码和日志归属契约；必要变更提供迁移与兼容说明。

优化不以增加配置项数量为目标。能够从当前上下文推导的范围、身份和版本，应直接展示并允许核对；需要用户决策的行为必须说清影响。

## 2. 角色、主流程与成功标准

| 角色 | 主要任务 | 应掌握的概念 | 系统应承担的工作 |
|---|---|---|---|
| 业务配置员 | 选择字段、配置条件/评分、准备样例、核对结果、送审 | 业务指标、条件、结果、版本 | 正确引用、类型推荐、校验、错误定位、未保存保护 |
| 数据接入人员 | 配置 API/DB/SFTP/模型/函数供复用 | 协议、参数、响应、凭据和运行限制 | 分步验证、模板、状态说明、敏感信息保护 |
| 审核人员 | 比较变更、检查影响、批准或退回 | 业务变化、引用影响、测试证据 | 展示精确差异、证据有效性、批次依赖和风险 |
| 运维人员 | 部署、监控、容量、备份恢复 | 拓扑、资源、队列、持久化 | 可测量的健康状态、告警、恢复指引、验收报告 |

四条端到端主流程：

- **首次配置**：创建项目草稿 → 审批生效 → 选择已有业务字段或补建字段 → 选择规则类型 → 编辑 → 样例测试 → 保存修订 → 回归 → 提交审批 → 发布 → 核对线上版本和日志。
- **接入新数据**：选择项目/全局范围 → 配置连接和鉴权 → 测试连接 → 配置请求/查询与结果取值 → 样例验证 → 保存审批 → 在变量或规则中选择 → 回到原规则验证。
- **修改已发布策略**：选择基线版本 → 编辑草稿 → 查看差异与影响 → 重新取得回归证据 → 审批 → 发布 → 查看运行结果 → 必要时按原版本及其依赖回滚。
- **故障定位**：从项目/日志定位执行 → 确认修订、来源及失败阶段 → 查看对应配置/依赖 → 判断可重试条件 → 修复或恢复 → 验证结果与副作用没有重复。

建议验收指标，需先在明确设备、数据规模和角色权限下建立基线：

| 指标 | 验收目标 |
|---|---|
| 配置正确性 | 同一配置在页面回显、保存、编译、服务端执行、SDK 支持的本地执行中语义一致 |
| 编辑安全 | 取消离开保留全部输入；保存失败保留输入；重复点击不创建重复资源；迟到响应不覆盖新状态 |
| 状态可理解 | 每个阻塞状态有原因、当前版本、可用动作；无权限时说明所需权限 |
| 业务可用性 | 5 名目标角色用户完成任务实验；记录成功率、时间、回退次数、求助次数；首轮目标为至少 4 人独立完成基础规则流程 |
| 大目录交互 | 2 万引用基线下，搜索/回显/切页分别测 P50/P95 与峰值内存；以无卡死、无错选及相对基线改进验收 |
| 运行容量 | 固定机器、模型、依赖延迟、并发与追踪开关，记录 P50/P95/P99、错误/拒绝率、CPU、GC、队列和日志积压 |

## 6. 关键需求的实施约束

### 6.1 配置保护与异步请求（R04、R07、R17）

- 初始化完成后记录基线；显示标签同步不能被当作业务编辑，更不能修改条件或数据。
- 保存锁应覆盖校验和请求全过程；表单、关闭、版本切换与重复提交使用同一状态。
- 请求结果必须绑定发起时的资源、版本和查询条件。关闭、切换、新建后，旧响应不得覆盖当前状态。
- 保存失败保留输入和清除凭据意图；取消离开保留全部内容；确认放弃清除敏感内存。
- 资源草稿保存、审批提交、审批通过和发布完成分别反馈，不用笼统“保存成功”代替。

### 6.2 测试模式与副作用（R20）

复用现有 `VariableResolveOptions.dryRun`、`offlineReplay`、来源快照和结果追踪，不新建一套执行引擎。建议在执行前区分：

| 模式 | 取值和动作 | 页面必须说明 |
|---|---|---|
| 纯计算预览 | 使用输入/已准备样例；阻止真实名单写入；未提供的外部来源明确报缺失 | 哪些来源被替代、哪些动作被跳过，结果可否用于回归 |
| 真实依赖联调 | 按明确范围访问当前数据源；有写入的动作需明确纳入本次操作 | 将调用哪些来源、可能计费、目标名单、超时预算及幂等标识 |
| 历史离线回放 | 使用执行时快照；禁止回退为当前线上来源 | 快照完整性、版本身份、缺失来源及与原执行的差异 |

版本来源（画布/草稿/发布版本）与执行模式是两个独立概念，界面不能只说明前者。测试用例必须覆盖缺失来源、嵌套子规则、函数内取值、外数重试、名单动作、并发与失败重试。

### 6.3 矩阵与评分（R12）

元信息刷新只更新展示和类型信息。主动更换维度时，应先说明原分段和已有结果如何处理。排序、增删分段不能仅按旧数组下标把结果搬到其他业务条件下。对高维组合先算规模，再生成编辑区域；上限应来自浏览器和编译容量实验，超限时给出减少分段或拆分规则的建议。

评分卡需明确总分、权重、缺失值和等级边界。零命中、多个条件同时命中、相邻区间端点、负值、小数及大整数都应使用实际执行结果验证。

### 6.4 引用目录（R11）

目录索引至少包含身份、类型、范围、版本和展示名。已选内容应能按 ID 回显，即使不在当前搜索页。请求取消、目录不可用、无权限和确实无结果须区分。缓存键包含用户/权限版本、项目、目录身份及版本；身份切换清理缓存。冻结制品目录与当前可编辑目录继续分离。

### 6.5 运行与性能（R24、R25、R31、R34）

- 固定运行环境与负载后再比较；记录启动预热、冷/热缓存、追踪开关和资源池配置。
- 外数并发不能越过依赖顺序或供应商限流；同一执行共享调用仍必须保持幂等。
- 过载验收包含拒绝、取消、超时、恢复和队列积压，不能只测平均响应时间。
- 模型预热遭遇瞬时数据库/文件故障后，应能查看失败目标并重新验证；失败期间保持 readiness 门禁，不通过隐藏失败或关闭预热获得就绪。
- 按稳定项目 ID 查询需要相应索引与迁移方案；历史未知归属不能通过当前编码猜测补入。
- SDK 日志缓冲有上限和重试计数，应核实客户的丢失容忍要求；如需持久补报，先定义存储、清理、幂等和磁盘上限。
- 每项性能修复保留前后数据，禁止通过关闭常量保护、追踪归因或权限过滤获得“提升”。

## 7. 验收与回退清单

每项需求交付均记录：代码路径、用户触发步骤、期望结果、异常路径、测试、真实 UI 验证和尚未覆盖的环境边界。

| 维度 | 必须覆盖 |
|---|---|
| 数据语义 | ID/ref_type、精确大小写、大整数 ID、字段改名、固定版本、全局/项目资源 |
| 生命周期 | 草稿、审批中、批准、发布、下线、回滚；依赖变化后的证据失效 |
| 表单 | 新建/编辑、取消/离开/刷新、慢响应/失败、重复保存、凭据保留/替换/清除 |
| 执行 | 零/单/多命中、空值、来源异常、嵌套调用、异步等待/恢复、动作幂等 |
| 权限 | 全局只读、项目只读、SELECTED 空项目、项目覆盖、原生函数权限、会话失效 |
| UI | 宽屏与 560px 窄屏、明暗主题、键盘、表格字段排序/隐藏/重载、错误定位 |
| 运行 | 无新增 deprecated/unchecked 告警；健康与预热；服务结束主动清理；测试跳过如实列出 |
| 交付 | 可复核差异、测试证据、配置迁移/索引方案、已有制品生效范围、回退办法 |

代码级回退与业务版本回滚分别设计。涉及新配置字段时提供缺省行为；涉及 SQL 索引时提供幂等升级和目标库验证；涉及不可变制品时通过新修订发布，保留旧版本供正常回滚。
