# 平台请求与响应契约

管理端、开放接口、HTTP/SDK 运行时和 Java 客户端共用的契约统一放在现有 `rule-engine-model` 模块，包名为 `com.hengshucredit.rule.model`，不新增独立模块。契约类不依赖 Spring 或规则执行器。`PlatformCode` 是平台结果码、固定描述及 HTTP 状态映射的唯一来源；`ApiResponse` 提供 JSON 外层，`RuleExecutionRequest` 提供规则执行请求。

## 结果判断

未启用对外映射时，成功响应使用字符串 `"000000"`，固定描述为 `"成功"`。业务拒绝、人工复核等属于规则的业务输出，正常完成计算时仍是成功。使用响应外层 `success` 判断平台结果，不要把业务数据中的 `code` 或 `success` 当成平台结果。

```json
{
  "code": "000000",
  "message": "成功",
  "success": true,
  "detail": null,
  "traceId": "root-trace",
  "data": { "result": { "decision": "REJECT" }, "success": true }
}
```

失败响应的 `message` 来自默认字典或已生效的对外映射，具体字段、校验或执行原因放在 `detail`；已有 `errorMessage` 保留为执行详情。调用方判断外层 `success === true` 确定平台操作成功，不根据描述或可能合并的对外 code 猜测。

```json
{
  "code": "100001",
  "message": "入参校验失败",
  "success": false,
  "detail": "年龄必须大于 0",
  "data": null
}
```

`data` 和 `traceId` 等可空字段在部分序列化出口可能省略。没有开始执行的请求不虚构执行 trace。错误响应可以保留已获得的追踪、校验明细或中间状态。

## 编码规则

默认标准码为六位字符串 `DMMNNN`：`D` 为领域，`MM` 为子类，`NNN` 为原因序号。必须按字符串传递，保留前导零。

系统配置支持将标准码映射为对外 `code` 和 `message`，多个标准码可共用同一个对外 code。启用后应使用 `success` 判断成功，不能仅依赖 code；HTTP 状态、执行进度和重试语义仍由原标准码决定。响应 Header `X-Rule-Standard-Code` 与 `X-Rule-Code-Mapping-Version` 保留原码及映射版本，Java 客户端按原码执行内部判断。服务端、SDK 和 runtime 需一起升级，配置与生效方式见 [系统配置](system-settings.md)。以下码表仍描述内部标准码及未启用映射时的默认返回。

| 领域 | 含义 | 示例 |
|---|---|---|
| `0` | 唯一成功结果 | `000000` |
| `1` | 请求格式、参数与业务约束 | `100001` 参数校验，`100003` 格式无效 |
| `2` | 规则、模型、实验执行 | `200001` 执行失败，`201001` 规则不存在，`202001` 模型失败 |
| `3` | 凭据、会话、访问限制 | `300001` Token 失效，`301001` 控制台会话失效 |
| `4` | 容量、超时、幂等及执行进度 | `400001` 容量受限，`400004` 幂等冲突，`400006` 等待外数 |
| `5` | 资源、产品授权与配额 | `501001` 资源不存在，`501002` 资源冲突 |
| `6` | 外数、数据库、名单、文件依赖 | `601001` 外数失败，`602001` 数据库失败 |
| `7` | 审批与发布治理 | `700001` 治理冲突，`700002` 发布前校验失败 |
| `9` | 系统及上游通信协议 | `900001` 系统异常，`900003` 上游响应格式无效 |

完整字典见 `rule-engine-model/src/main/java/com/hengshucredit/rule/model/PlatformCode.java`。前端目录文件由 `node scripts/generate-platform-contract.mjs` 生成；单元测试逐项核对两端字典，禁止单独修改前端码表。日/月配额码仍为预留编码，不代表已实现配额策略。

## HTTP 状态和执行状态

HTTP 状态由平台结果码映射，所有业务响应统一使用 `ApiResponse` 和类型化 `PlatformCode` 工厂，不再提供数字码工厂。

| HTTP | 平台含义 |
|---|---|
| 200 | 操作成功，平台码 `000000` |
| 202 | 等待外数或结果尚未就绪；不是最终成功 |
| 400 / 406 / 413 / 415 | 参数、请求大小或媒体类型问题 |
| 401 / 403 | 身份失效或权限不足 |
| 404 / 405 | 资源不存在或方法不支持 |
| 409 | 幂等、资源状态或治理冲突 |
| 422 | 已识别的执行失败或业务约束不满足 |
| 429 | 限流或执行容量不足；保留 Retry-After |
| 500 / 502 / 503 / 504 | 系统、依赖、可用性或超时问题 |

`executionStatus` 表示执行进度，与平台码分别保留。查询状态这一操作成功时返回 `000000`，其 `data.status` 可仍为等待中；执行请求本身等待外数时返回 `400006`。网络中断或超时可能无法确定是否完成，返回或抛出 `400007` 时先使用已知 trace 查询，不能无条件重放可能产生外部调用或计费的请求。

## 各入口

- 管理和同步接口直接使用公共 `ApiResponse`；旧 `R` / `Result` 门面已删除。明确的执行结果实现 `PlatformOutcome`，外层继承其结果码；任意业务 Map 不会被猜测为平台状态。
- HTTP/SDK 运行时使用同一请求、外层和 HTTP 映射，逐请求传递 clientAppName/traceEnabled，不修改共享客户端配置。上游拒绝的具体码与 trace 被保留，不再全部转换成 502。
- 两种 Java 客户端共用严格 HTTP 响应解析器，校验平台码、固定描述、success 和 HTTP 映射一致性。执行、同步、Token 交换和日志上报均使用该解析器；Token 交换只接受相对有效期字段。已返回执行结果的失败通过 `RuleResult.code/message/detail` 表示；没有有效执行结果的调用失败抛出带平台码的异常。成功、业务拒绝、调用失败不能混为一类。
- 开放接口固定外层 `code/message/detail/success/traceId/data`，只允许定制 data 模板和业务响应头。旧 envelopeTemplate/dataPath 配置已移除，不再输出 retCode/payload 等别名；追踪和重试响应头由平台控制。
- 文件下载、供应商原始报文和 Actuator 等基础设施专用协议保持原内容；平台自身产生的 JSON 结果和错误使用公共协议。供应商业务码保留在业务数据内。
- 前端规则、表达式、函数和外数测试请求显式保留失败执行结果，便于展示 trace；入参、依赖和系统错误的诊断均可展示，鉴权和资源授权错误始终拒绝。下载接口的 JSON 错误体也统一解析。

## 迁移与验证

这是接口契约变更。服务端、前端、两种 SDK 与 runtime 应同步升级。外部调用方须将整数 `200` 判断迁移为字符串 `"000000"`，并把具体失败原因的读取位置从 `message` 调整到 `detail`；不得继续将成功 HTTP 状态等同于规则执行完成。HTTP 202 仍需检查平台码。

导出的 HTML、OpenAPI JSON、页面预览和 Java SDK 结果均采用新契约。历史保存的请求/响应样例属于用户内容，不自动改写，重新保存样例时使用新格式。

回归覆盖成功与业务拒绝、真实执行失败、鉴权和参数错误、等待外数、限流、上游未知、模板覆盖保护及前后端字典一致性。

## 2026-10-22 复核修正

- 开放接口纳入请求体缓存和大小限制，HMAC 校验使用真实请求体，超限统一返回 `100006 / HTTP 413`。
- 失败工厂禁止使用成功码；函数执行失败使用 `204001`，外数调用失败和降级结果使用 `601001`，保留诊断数据。
- 补齐缺失 Header、Query 参数、上传部分和不可接受响应类型的框架异常；即使请求的 Accept 不接受 JSON，错误出口仍返回平台 JSON，避免空的 406 响应。
- SDK 严格校验结果码、描述、success 和 HTTP 状态的一致性，保留外层 detail、traceId 及 Retry-After；不再接受旧整数业务码和 Token 绝对时间兼容格式。
- HTTP/SDK 运行时逐请求传递执行选项；本地 SDK 的根执行和子规则共享本次追踪开关，后续调用的默认配置不受影响。
- 已同步前端字典、开放接口编辑与预览、HTML/OpenAPI 文档生成器、Java 接入说明、压测断言和部署文档清单。平台码必须按字符串读取，所有组件需同时升级。
