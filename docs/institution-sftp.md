# 机构凭据登录 SFTP

合作机构可用同一套凭据调用全局规则、分流实验，并通过标准 SFTP 客户端交件。开通后，客户端直接连接 SSH 的域名和 TCP 端口。首次连接前，请向部署管理员取得端口和主机密钥的 SHA-256 指纹。部署管理员可参考[公网端口与 Nginx Proxy Manager Streams 配置](sftp-public-access.md)。

## 为合作机构开通登录

1. 在控制台的规则列表或分流实验列表打开 **机构鉴权**。管理凭据的账户需要全局的机构鉴权管理权限。
2. 新增鉴权配置，选择已有机构或填写新机构名称。**管理归属项目**可留空，也可为同一项目登记多家机构。此字段用于管理归类，机构执行全局规则和实验时保持独立身份。
3. 选择鉴权方式，填写凭据并打开 **开通 SFTP**。已有配置可通过 **编辑** 开通。保存后通过 **完整值** 查看本凭据的 SFTP 登录名。
4. 把地址、端口、主机指纹、登录名和对应凭据交给合作方。配置了 IP 白名单时，应填写 SFTP 服务实际看到的来源 IP 或 CIDR。经过 TCP 代理时服务可能看到代理地址，部署管理员可在入口限制合作方出口 IP。

| 鉴权方式 | SFTP 用户名 | SFTP 密码 |
| --- | --- | --- |
| Basic | 配置的账号，大小写保持一致 | 配置的密码 |
| API Key | **完整值**中的专属 SFTP 登录名，形如 `auth-…` | API Key 完整值 |
| HMAC-SHA256 | 配置的 Access Key | 配置的 Secret 完整值 |

HMAC 的 HTTP 调用继续签名。SFTP 客户端把同一 Access Key 和 Secret 填入账号与密码栏，密码在 SSH 加密连接中传输。引擎服务账号供业务节点访问存储，控制台上传账户沿用原有公钥登录方式。

## 使用 OpenSSH 或图形客户端交件

以下命令使用示例地址和端口，将登录名和地址替换为部署方提供的值。密码在客户端提示时输入。

```bash
sftp -o PreferredAuthentications=password -P 2222 partner-login@sftp.example.com
```

在 WinSCP 或 FileZilla 中选择 **SFTP**，填入相同的地址、端口、用户名和密码。首次连接核对主机指纹。以下示例将本地文件上传为临时名，传完再改成供规则读取的文件名。

```text
pwd
put request.json request.json.part
rename request.json.part request.json
ls
get request.json verified.json
bye
```

## 让全局规则读取机构交件

在全局规则使用的 SFTP 变量中选择 **引擎内置 SFTP**。远端路径填写相对于机构凭据登录根目录的文件名，例如 `request.json` 或 `batch/request.json`，也可从规则入参取该相对路径。上传和执行应使用同一条鉴权配置。系统根据已验证的机构 ID 和凭据 ID 定位文件；两条凭据可分别上传同名文件，同一机构的不同凭据也有独立目录。

已有项目调用可继续读取 `u7/result.json` 这类控制台账户项目路径。为普通项目凭据单独开通 SFTP 后，使用该凭据执行项目规则时，可通过 `@inbox/result.json` 读取自己的交件。

## 轮换与停用

编辑密码、重置密钥、关闭 SFTP 或停用鉴权配置后，已登录客户端在下一次文件操作时会断开。轮换后使用新密码重新登录，原目录与文件保留。已开通配置仍受 SFTP 的来源限速、连续失败封禁和文件传输限速约束；管理员可在 **SFTP 管理 → 引擎 SFTP 服务配置** 查看并解除现有封禁。
