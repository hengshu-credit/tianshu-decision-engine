# 规则外数与名单动作

规则集、决策树和决策流的动作编辑器支持“调用外数”和“名单落库”，条件分支、Switch 和循环内也可添加。动作按配置顺序执行，未命中条件不触发。

## 调用外数

选择 API 后，执行到该动作才调用统一外数链路。可选择 OBJECT/MAP 变量或对象字段接收完整调用结果，包括 `request`、`response`、`body`（组装结果）、`status`、鉴权记录和追踪字段。后续条件、赋值及表达式可通过字段选择器访问 API 的完整结果或具体字段。

API 变量、数据对象原有隐式取数保持不变。显式与隐式调用使用同一请求级缓存；相同 API、配置及请求参数复用结果，参数改变则按新的请求执行。关联保存 API ID 和字段 ID，不依赖业务名称。

## 名单落库

选择一个或多个名单，并通过字段选择器添加内容字段，每个字段单独指定手机号、身份证、邮箱等内容类型。空值跳过，整个对象或集合不能作为一条名单内容写入。

| 操作 | 行为 |
| --- | --- |
| 加入并合并有效期 | 保留更早生效时间与更晚失效时间；永久有效优先 |
| 加入并覆盖有效期 | 使用本次配置，可从有限期改为永久 |
| 仅新增 | 已存在且未失效的内容保持不变；否则新增或重新启用 |
| 从名单剔除 | 按名单、内容类型和内容精确匹配，逻辑停用并保留操作记录；不存在时不新增 |

有效期支持执行后的天/小时/分钟、指定失效时间和永久。相对有效期以本次规则执行开始时间为起点，随任务持久化保存，恢复重试不会顺延。一次任务的多名单写入与操作日志在同一数据库事务内提交。

## 异步隔离与恢复

规则线程只负责复制内容并将任务写入本机持久化日志，`fsync` 成功后记录 `QUEUED`。名单数据库写入由单独工作线程和专用单连接池执行，不借用引擎查询连接，不回退到调用线程。后续规则不等待落库，同次执行中的后续名单查询不能假定已经读到这次写入。

数据库暂不可用、事务失败或服务中断时，任务仍保留在恢复日志内。工作线程按原顺序持续退避重试，最长间隔一分钟，不因达到重试次数而丢弃任务。重启后使用同一目录恢复。数据库回执 `rule_list_action_receipt` 与名单、审计一起提交，处理“事务已提交但队列尚未确认”的重复交付。恢复读取使用有界批次，积压保存在磁盘。

管理接口 `GET /api/rule/ops/execution-metrics` 的 `listActions` 返回积压采样、存储状态、连续失败次数、错误及下次重试时间。对象、集合、超长内容及非法有效期在交接前拒绝，避免不可写内容堵塞队列。名单停用或权限范围变化可能需要恢复资源可用性后才能继续；已接收任务不会被静默删除。

配置 `RULE_LIST_ACTION_JOURNAL_DIR` 指定恢复目录，默认 `./logs/list-action-journal`；多副本 Compose 同时开启 `RULE_LIST_ACTION_JOURNAL_SCAN_PARENT=true`。Compose 已放入 `server-logs` 持久卷；每个 server 实例使用独立目录，启动时会扫描同一父目录中的历史实例目录并通过文件锁接管未处理任务，重建实例时仍需重新挂载原卷。备份与容量监控应同时覆盖恢复目录和数据库回执；未处理完任务时禁止删除恢复卷或回执。

可恢复交付的前提是持久化介质可写且未丢失。本地磁盘满、目录不可写或卷损坏时，动作会在追踪中明确返回 `REJECTED`，并写服务错误日志；规则执行会失败，避免把未可靠接收的名单副作用伪装成成功。需要跨主机故障恢复时，应使用持久卷及恢复流程。规则本地纯计算 SDK 不执行外数或名单写入，需使用服务端执行模式。
