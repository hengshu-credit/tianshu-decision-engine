# 变量、模型与历史统计执行复盘（2026-09-23）

## 本轮结论

本轮已实现“同一根规则（含子规则）共享首次取值”的执行契约，并贯通模型入参、字段 ID 依赖、历史结果记录和日志回溯。模型上传、字段绑定、审批、规则发布、页面测试和正式 HTTP 调用均通过实际页面完成，未用数据库写入绕过配置步骤。

这不是“所有能力已无问题”的声明：数据库真实连接仍有验收阻塞，图规则的叶字段级懒执行仍有下文列出的边界。代码没有 commit，没有创建分支；共享工作区内其他任务的改动未被撤销。

## 问题分类与处理

| 分类 | 实际问题 | 本轮处理 |
| --- | --- | --- |
| 执行契约设计不足 | 是否执行来源曾受请求中是否有同名值、刷新参数和子规则进入次数影响 | 根执行共享缓存；变量、模型按 ID 记忆首次结果，同一 API ID 共享一次逻辑调用；新根请求重新建立缓存 |
| 代码逻辑缺陷 | 请求方填入 API、名单、衍生、模型同名结果可干扰真实计算；空值或失败可能触发再次解析 | 不把请求值视为已计算凭据；缓存成功、空值、跳过、失败及兜底状态，后续引用重放真实结果 |
| 代码逻辑缺陷 | 模型取值与原生输入绑定分散，可能重复求表达式、读旧名称、对空值回退到同名请求字段 | 统一操作数解析；内部区分已绑定原生输入与原始请求；保留 ID 引用上下文，冻结执行不回读实时函数 |
| 代码逻辑缺陷 | 模型入参/默认值/输出转换中的上游依赖、对象父字段未完整进入制品 | 补全变量、常量、对象字段和函数的依赖闭包；对象绑定沿 ID 解析，多层衍生展开到原始输入 |
| 代码逻辑缺陷 | 模型审批修改字段时删除重建全部 I/O，导致字段 ID 漂移 | 更新已有且归属当前模型的字段，只删除被移除字段；新增字段才生成新 ID；可空绑定支持真正清除 |
| 代码逻辑缺陷 | 模型引用数据对象字段时，审批错误地将字段 ID 当成数据对象资源 ID | 共享字段到所属对象的治理引用转换，变量和模型使用同一处理方式 |
| 功能链路缺陷 | 模型“发布”审批仅更新启用状态，没有可执行版本快照 | 启用审批接入模型发布服务；实际 UI 验证模型 v2 快照及子规则发布成功 |
| 前端功能缺口 | 脚本设计器没有模型输出分组；模型输出路径可能取输出目标名而不是原生输出名 | 展示模型输出并持久化引用 ID；输出引用路径优先使用原生字段名 |
| 历史统计设计不足 | 历史侧字段资格、采集时点与执行结果记录缺少明确契约 | 默认可回溯请求输入和当次三方逻辑调用日志；其他结果必须显式开启“记录字段结果” |
| 历史记录逻辑缺陷 | 依赖当前名称解释旧记录、只存输入不存指定结果、子对象字段开启记录后仍可能漏写 | 新日志按字段类型和 ID 存储；记录实际计算结果；对象子字段从可信来源首次快照提取，不读伪造值或后续修改值 |
| 历史查询逻辑缺陷 | 使用当前 API 绑定筛选旧调用日志，换接口/换来源后会丢失旧字段结果 | 从历史根 trace 读取当次逻辑调用日志，按已保存的字段 ID 合并；兼容显式 API 节点的日志 |
| 历史可靠性不足 | 日志丢失、重试计数、窗口截断或超限可能返回不完整统计 | 统计用逻辑 API 日志同步写入；不把重试尝试当多次结果；缺失/歧义/超量明确失败，有行数、内存与查询时间限制 |
| 代码逻辑缺陷 | 实验路由依赖投影可能丢失条件直接引用的衍生节点 | 保留稳定操作数引用与原始入参投影；已发布路由规则使用冻结执行链路 |
| 配置体验不足 | “强制刷新”开关与根规则只取值一次的要求冲突；历史选择器暴露不可回溯字段 | 去掉误导开关并说明一次执行语义；历史字段选项受来源/记录开关约束，后端也进行资格校验 |

## 当前执行口径

- 衍生、名单和数据库变量按变量 ID 取值一次；模型按模型 ID 计算一次，父子规则共享。多个外数变量绑定同一接口 ID 时共享一次逻辑响应。
- 接口内部的失败重试照常遵循外数管理配置，不算多次逻辑取数。接口自身跨请求响应缓存仍保留，不能把它与根规则内复用混为一谈。
- 请求输入与原生模型字段不是一回事。配置模型输入时选择变量/常量/对象字段，运行时先解析上游再传入模型原生字段。带 ID 的绑定不依赖保存时的展示名称。
- 历史默认来自已登记请求输入及当次 `API_INVOKE` 字段快照。名单、衍生、数据库、常量、模型输出等其他字段需开启记录；未执行的来源不会仅为记录而额外计算。
- 只有成功的 `CLIENT_SERVER` 根执行进入当前生产统计；业务拒绝但引擎执行成功仍是一条进件。管理端预览、规则测试和子规则不会另算一条进件。本次执行不计入自己的历史窗口。
- 新增记录开关不回填旧数据。旧无 ID 快照日志不按当前名称推测；已发布模型/规则修改记录配置后，需要重新发布相关制品。

详细口径见 [衍生变量文档](derived-variables.md)。

## 尚需处理的边界

1. **真实数据库来源联调未完成。** 现有共享数据源使用 root 账户，连接报 `Public Key Retrieval is not allowed`。没有放宽认证、改共享密码或创建数据库账号。需要可用的只读连接与明确允许查询的表/SQL，再完成 DB → 模型 → 父子规则的真实链路验收；现阶段只有相关解析/绑定测试，不能称作数据库端到端通过。
2. **后续已按用户明确边界完善对象引用。** 引用型叶子支持可选懒加载，默认关闭；已有子字段优先，“仅复用结构”不取数，对应来源状态读取亦按需触发。不是全局所有字段都改成懒加载。新的实现与验收见[数据对象取值说明](data-object-reference-resolution.md)。
3. **历史容量与数据治理仍是交付门禁。** 当前日志扫描有硬上限，不代替生产容量测试、字段级索引或增量预聚合；需按业务设置日志保留期及敏感字段权限。离线 SDK 不具备服务端历史库，统计需走服务端执行。

## 不应误判为产品缺陷的验收问题

- 自动化点击 Element Plus 隐藏原生 radio/switch 被可见控件遮挡：改用实际可见控件，不修改产品组件。
- 页面尚未完成加载时写入编辑器导致测试脚本内容被初始化覆盖：修正验收脚本时序，不把空脚本校验报错当编译器缺陷。
- 运行中的开发后端与 Maven 重编译同时使用 `target/classes`，短暂出现类加载失败：停止服务、完成构建测试后重新启动复验，不通过修改业务代码掩盖验证环境竞争。
