# 数据对象、引用与批量导入说明

更新日期：2026-09-16。

## 数据对象层级

- 点击对象的展开箭头或非操作区域查看字段；点击有子字段的字段行可逐级展开。
- “展开全部 / 收起全部”控制当前页的字段层级，展开状态按字段 ID 保存。
- 字段每页显示 20 个一级字段，子字段随父字段保留在同一页，避免父子关系被分页拆开。
- 展开区固定在表格可视宽度内，字段区有独立滚动范围，列头和操作入口保持可见。

## 统一引用入口

字段列表与编辑表单统一显示“引用变量”，可选来源分为变量、常量、数据对象。

| 目标 | 用途 | 类型要求 |
| --- | --- | --- |
| 变量 | 当前字段未传值时，从变量取值 | 同类型或兼容类型族；数值类型相互兼容 |
| 常量 | 当前字段未传值时，使用常量的固定值 | 同类型或兼容类型族；声明了列表元素类型时还会校验常量元素 |
| 数据对象 | 复用另一数据对象的字段结构 | OBJECT/MAP 字段，或元素为对象的 LIST/ARRAY/SET 字段 |

对象与映射、列表与数组/集合分别按兼容类型族处理。数据对象引用不等同于获取另一对象的一份运行时值。

引用只能指向已启用的全局资源或字段所属项目的资源；全局对象不能引用项目资源。选择时和保存前均调用服务端校验，审批生效前再校验。类型不符、对象循环引用、结构中同名子字段冲突、失效或跨项目资源均不能绑定。

引用通过 `refVariableId` 或 `refObjectId` 保存，不通过编码回溯关联。更改类型后需要重新选择引用；清除引用会清除数据库中的旧 ID。编辑引用不会把展示用的完整路径写回原始脚本名称。

已有的列表运行时边界仍保留：列表元素内部不直接把一个变量或常量值逐项填入，需在列表字段上整体引用；内部 OBJECT 字段可以复用数据对象结构。界面会给出对应说明。

## 五种导入方式

所有导入都经过“解析 → 审批草稿 → 依赖预检 → 提交审批 → 通过生效”。看到“审批草稿已生成”时，有效数据尚未改变。单条结果可直接进入对应审批详情，多条结果进入审批管理。

| 方式 | 输入与适用场景 | 支持内容与边界 |
| --- | --- | --- |
| Java 实体类 | 粘贴类定义，或上传 UTF-8 `.java` 文件 | 解析有访问修饰符的实例字段，支持基本类型、数组、List/Set/Collection、Map；类名及字段名原样保留。自定义对象类型需先存在并生效，不能将同批次尚未生效的对象当作已建立的引用。不是完整 Java 编译器，record、继承字段和复杂泛型需改写为明确字段声明。 |
| JSON 对象 | 填写对象编码，粘贴实际 JSON 对象样本 | 支持嵌套对象及对象数组，按样本顺序保存父子字段。数组从首个非 null 元素推断结构，应提供字段完整且元素同类型的样本；混合基本类型数组报错。空数组不猜测元素类型，后续可在编辑表单补充；null 标量暂按 STRING 识别。 |
| DDL 建表语句 | MySQL 风格 `CREATE TABLE` | 支持多表、一行多列、跨行列定义、数值精度及 COMMENT。索引/约束不生成字段，也不再截断后续列。只解析文本，不连接数据库、不执行 DDL；非 MySQL 方言、复杂表达式及不支持的标识符写法应先整理后导入。 |
| Java 常量类 | `static final` 常量声明 | 支持字符串、布尔、十进制数值、字面量数组、`List.of`、`Arrays.asList`、`Map.of` 等有限的集合初始化形式。字符串转义会还原为值；不执行任意方法、字符串拼接或变量计算，不支持的表达式会报错。 |
| JSON 常量 | JSON 顶层键值对象 | 每个顶层键生成一个常量。基本类型直接保存，数组作为 LIST、对象作为 MAP 整体保存；不再静默丢弃结构化值。空字符串有效，顶层值为 null 时明确报错。 |

各导入弹窗提供格式说明、示例和“填入示例”。已有输入时不会覆盖内容；失败后保留输入，便于修改重试。提交期间禁止重复请求。

### 更新与冲突

- 同作用范围、同编码的资源生成更新草稿，不通过名称建立引用关系。
- 数据对象重导入时，匹配到的字段保留稳定 ID；未出现在新输入里的旧字段保留，不会被静默删除。
- 普通变量占用的编码不能被常量导入转换为常量。
- 同一批次的重复常量或对象编码会报错。
- Java 自定义对象依赖缺失、或依赖同批次尚未生效对象时，会提示先导入并审批依赖对象。

### 最小示例

JSON 对象（对象编码另填 `RiskRequest`）：

```json
{
  "User_ID": "U001",
  "profile": { "age": 30 },
  "apps": [{ "app_code": "A", "enabled": true }]
}
```

JSON 常量：

```json
{
  "MAX_AGE": 65,
  "ENABLED": true,
  "CODES": ["A", "B"],
  "LIMITS": { "max": 1000 }
}
```

## 本次检查中修复的问题

1. 字段树按扁平序号分页导致子树被拆分，以及展开区随宽表溢出。
2. 引用常量被排除、对象依赖仍需手填编码、引用绑定缺少统一的类型/范围/循环校验。
3. 清除引用时 ORM 忽略 null，可能保留旧引用 ID。
4. 嵌套 JSON 输出顺序与审批导入的父字段 ID 分配顺序相反。
5. JSON 常量跳过数组、对象，并将 null 改为空字符串。
6. DDL 按行取字段，在一行多列或约束后仍有列时漏字段。
7. Java 数组、带空格的泛型声明漏解析，以及常量表达式被保存为错误文本。
8. 对象字段引用常量时，制品依赖仍被错误地标记为普通变量。
9. 嵌套对象整体删除/下线时，内部子字段被误判为外部下游消费者；现在使用血缘节点的稳定 `refId` 与所属对象标识区分，真正外部依赖仍会阻止操作。

验证覆盖真实解析器到审批草稿的五条入口、嵌套父子 ID、字段名保留、引用兼容/拒绝/解除、常量运行时取值和制品依赖类型。浏览器验证使用本地服务，从页面操作完成导入及审批流程。
