## 性能优化后的处理结果

- **P1，代码已修复，生产待更新。** 提交 `1386d9bb` 已将台账入口纳入服务端页面识别并保留 `ledger:view` 权限校验。本次补上四个子页签的真实上报载荷回归。在独立 MySQL、Redis、Spring 和 Vite 环境中，用 Chrome 登录并实际点击四个子页签，每轮 9 次访问上报均返回 HTTP 200、业务码 `000000`。两轮之后直接查询审计表，四个页签各有两条 `SUCCESS` 记录，模块为 `ledger`，页签名称正确。
- **P2，提示已修复，生产配置需按实际资源核实。** 页面逐项使用服务端原始原因，原因相同的指标合并展示。未配置、引用无效和执行数据异常均保留各自的含义。在隔离环境验证七个未配置指标合并为一条说明，重新测试混合原因时分别展示三条。现有默认值初始化只在尚无公共配置且存在可用字段时补齐绑定，已有业务选择保持原样。
- **V1、V2 为预期说明或校验。** V3 的覆盖缺口已通过补采关闭。
- **性能巡检持续留证。** 在 `rule-engine-web` 构建 dist 后运行 `npx playwright test tests/e2e/navigation-responsiveness.spec.js -g 逐一点击`。巡检完成或中途断言失败时，结果目录中的 `navigation-audit.json` 会记录已完成计时、当前动作、浏览器异常、HTTP 与业务错误码、失败或取消的请求、界面提示、测试错误和截止时尚未结束的请求。请求按发起时的动作归属。CI 上传 `navigation-audit` 附件，保留 7 天。该测试使用受控的业务夹具，生产复采数据另见上方采样记录。
- **复验留证机制。** 正常巡检保存了 79 段交互、0 项报错；另在独立夹具中制造 HTTP 400、HTTP 200 携带失败业务码、网络失败、控制台错误、未捕获异常及界面警告，再故意触发定位超时。失败后仍能读取上述六类事件、已完成计时和中断原因，报告中未出现测试请求的敏感查询值或响应数据。
