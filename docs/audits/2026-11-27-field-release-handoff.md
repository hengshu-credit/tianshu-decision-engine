### 如何选择业务样例

决策表、规则集的样例覆盖优先级与多条件命中。决策树和决策流分别覆盖分支与早停。普通和复杂交叉表按行列组合或区间边界取值。两种评分卡验证初始分及加权贡献。QL 样例使用金额字段及布尔返回值。各例的业务规则、字段名和结果形状写在预览中。用于自定义规则前，应与当前修订的字段和配置核对。

在隔离项目中，通过选择器插入金额字段并保存 QL 规则。分别载入 `amount=1000` 与 `amount=999`，预期为 `true` 与 `false`。两次执行均符合预期，经界面保存为两个固定用例，重新批量执行 2/2 通过。另在返回数值的规则上载入布尔预期，确认引擎执行成功而业务校验失败。其他八类样例由组件测试逐类核对载入的请求与预期，本轮没有逐一搭建其说明中的业务模型。

### 如何阅读费用

“调用成功”反映模块的执行状态，拒绝或通过等业务结论应查看实际输出。一条根流水可包含多个模块、尝试或计费项。界面仅关联精确匹配的记录。数据库按项目、账户和币种计算可见合计，以十进制文本返回金额。暂未取得记录时可以刷新。夹具另覆盖缓存命中、查询失败、模型、名单、空跑组、试运行零费用及不同币种。实际供应商结算价格和生产账期仍需与供应商明细核对。

## 两套部署的演练结果

| 核对项 | 部署 A | 部署 B |
| --- | --- | --- |
| 已发布规则的最终修订与输出 | 修订 2，server 和 SDK 均返回 45 | 修订 5，server 和 SDK 均返回 46 |
| 独立恢复库 | 124 张表，0 项差异 | 124 张表，0 项差异 |
| SFTP 冷读 | 89,510 字节待检素材，备份与恢复端摘要匹配，并核对 1 项数据库文件引用 | 空文件仓，核对目录和主机公钥指纹 |
| 制品 | 恢复库含 2 个二进制决策制品，合计 5,271 字节 | 恢复库演练结束时含 3 个二进制决策制品，合计 7,904 字节 |
| 冲突处置 | 从控制台导出规则 ID 3 与对应固定用例 | 导入得到新规则 ID 4，再次预检显示同名冲突。采用后缀得到 ID 5。两条目标规则各有 1 份固定用例。 |

演练发现一次 SDK 收到发布通知后回源失败，旧 L1 项仍会应答。修复后，回源或脚本准备失败会使该规则的旧缓存失效，下一次调用重新读取已发布版本。同一通知重试仍然有效。验收包含已预填旧规则的回归用例，以及两个实际运行时的热更新。

## 复测入口

- 真实浏览器需要为两个独立环境预置可用的登录参数。发布前后执行、固定用例过期及 SDK 输出，可运行 [SDK 热更新用例](../../rule-engine-web/tests/e2e/optimization-runtime-update-live.spec.js)。`E2E_RUNTIME_BASE_URL` 指定被测 runtime。
- 在 A 和 B 中指定源已发布规则与目标项目，运行 [跨部署迁移用例](../../rule-engine-web/tests/e2e/offline-transfer-live.spec.js)。新用例使用 `E2E_TRANSFER_TARGET_URL`、`E2E_TRANSFER_RULE` 和 `E2E_TRANSFER_PROJECT`，通过界面下载和上传同一 ZIP。
- 使用 [备份恢复门禁](../../scripts/quality-gates/run-docker-backup-restore-gate.ps1) 指定数据库容器、源库、一个全新恢复库、已恢复的 SFTP 端点及备份归档。需要随后启动应用复跑业务时可传 `-KeepVerifiedDatabase`，仅在校验通过时保留新库。演练保留原数据库，将应用指向已验证的新库后重跑了启用的固定用例。
- [字段解释与收费验收](../../rule-engine-web/tests/e2e/field-and-execution-evidence-live.spec.js)覆盖输入缺失、零值、业务预期与收费明细。[跨角色用例](../../rule-engine-web/tests/e2e/optimization-live.spec.js)通过控制台建立三个角色，再逐人接手同一申请。

JDK 17 全模块编译和 Maven 测试通过。3,199 例中 3,123 例通过，76 例按环境条件跳过，失败和错误均为零。前端 ESLint、生产构建和 3,886 个 Vitest 用例通过。生产构建浏览器套件首轮通过 642/643 项。原导航用例把新增的变更交接页签也当作文章时间线，修正为核对该页签中的实际审批申请号后，唯一失败项复跑通过。真实服务验证使用了独立账户和数据库，演练结束后已停止。
