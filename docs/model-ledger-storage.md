# 多节点模型文件与台账素材

每个业务节点和导入器启动时连接部署指定的默认 SFTP。存储服务独占文件卷，数据库保存业务元数据、权限、模型版本和摘要。客户端每次建立 SSH 会话都校验配置的主机指纹，连接中断后可为后续操作重新建立会话。[部署、配置与切换步骤](../docker/README.md#启动独立-sftp)

| 文件 | SFTP 服务账户根目录下的位置 | 读取约束 |
|---|---|---|
| 进件、第三方结果 | `projects/<项目ID>/u<账户ID>/` | 按执行项目解释相对路径 |
| 个人上传 | `private/u<账户ID>/` | 按当前登录账户解析素材或模型导入路径 |
| 模型原件、冻结包 | `managed/objects/` 和对应的项目、制品引用 | 按 SHA-256 复用同内容，冷读校验作用域、绑定与内容摘要 |
| 已检测素材 | `managed/ledger/png/` | 执行素材可见范围检查，通过扫描后读取规范化 PNG |
| 待检或隔离的素材 | `managed/ledger/pending/<素材ID>/` | 限制大小并校验原始摘要，重试扫描或删除成功后清理 |

文件先写同一远端目录的临时文件，完成长度与摘要检查后改名发布。上传区与受管目录分开，模型替换仍经过影响分析和审批，历史版本引用的字节保持不变。每个节点可缓存已验证的不可变文件。常规模型上限 256 MiB，冻结包读取上限 512 MiB。

## 历史文件

旧管理库的 `rule_file_reference`、`rule_file_object`、`rule_file_object_part`、`rule_file_chunk` 保留用于迁移。仅当 SFTP 明确返回文件缺失时才检查历史来源。历史模型引用保持原值，载荷还原并核对摘要后复制到 SFTP。旧台账内联图片在首次读取时迁移，旧待检原件在重试扫描时处理。

切换前备份数据库、旧卷和 SFTP 卷，恢复验证应包含冷启动节点实际读取图片、模型与冻结包。已有跨主机旧卷的安装需按部署说明归并上传区。回退到旧 JAR 时使用匹配的切换前备份。
